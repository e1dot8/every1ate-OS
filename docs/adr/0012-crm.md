# ADR-0012 — CRM (lot 4)

1. **Pipeline** : 7 étapes exactes (enum `OpportunityStage`). Retour arrière autorisé et historisé ;
   une opportunité convertie en projet ne peut plus quitter « Gagné ».
2. **Montants** : `Decimal(12,2)` en base ; calculs en centimes entiers (`src/lib/money.ts`),
   jamais de flottant. Le pondéré = montant × probabilité (saisie, sinon celle de l'étape).
   Indicateur commercial uniquement : ni CA reconnu, ni trésorerie.
3. **Probabilités par défaut** : table `crm_stage_setting`, modifiables (Réglages CRM), journalisées.
   Gagné = 100 %, Perdu = 0 %, non modifiables.
4. **Historique** : `opportunity_activity` (échanges, réunions, propositions avec lien, notes,
   changements d'étape avec motif de perte). Les propositions sont des **liens**, pas des fichiers.
5. **Conversion idempotente** : `opportunity.projectId` est unique ; la création du projet verrouille
   la ligne de l'opportunité (`SELECT … FOR UPDATE`) dans la même transaction. Un second envoi
   renvoie le projet existant (`?deja=1`), sans doublon.
6. **Relances** : la passe horaire notifie le responsable commercial quand la date de relance est
   atteinte (une seule fois par date).
