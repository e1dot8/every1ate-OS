# Pilote interne — checklist des trois associés

Objectif (§25) : valider un **projet réel** de bout en bout avant l'usage courant.
Durée conseillée : 2 à 3 semaines. Chaque ligne cochée = constat partagé, pas une impression.

## Avant de commencer

- [ ] Déploiement de production effectué (`[deploy]`), `/api/health` = ok
- [ ] `CRON_SECRET`, `RESEND_API_KEY`, `APP_URL` configurés ; sauvegarde du jour verte dans GitHub
- [ ] Johan, Charles et Pierre ont activé leur compte et installé l'app sur iPhone (Plus › Installer)
- [ ] Seuils de gouvernance et règle de décision fixés ensemble (Finance › Gouvernance)

## Parcours à valider sur le projet pilote

- [ ] Opportunité créée, suivie (relances), passée à « Gagné » puis convertie en projet
- [ ] Projet créé depuis un modèle ; responsable global confirmé ; lots et tâches ajustés
- [ ] Roadmap : au moins un déplacement avec cascade, un sans cascade
- [ ] Temps saisi par chacun (chronomètre et saisie manuelle), une correction faite
- [ ] Une tâche bloquée avec motif ; l'escalade 48 h reçue par le responsable global
- [ ] Budget initial, coûts engagés, échéancier, un encaissement, un import CSV Pennylane/Qonto
- [ ] Une révision de budget au-delà du seuil, décidée collectivement
- [ ] Réunions dans le calendrier ; abonnement Google ou Apple actif sur un téléphone
- [ ] Documents Drive rattachés au projet et aux tâches
- [ ] Cockpit consulté sur mobile (semaine, mois)
- [ ] Clôture : checklist complète, bilan saisi, projet archivé puis consultable

## Retours

Noter chaque anomalie (écran, étapes, attendu/obtenu) ; elles sont traitées avant l'usage courant.
